## 4.1 工具的四要素

在开始写代码之前，你必须理解一个核心问题：在 Harness 中，一个"工具"到底是什么？

一段最直接的回答是：**一个工具 = 一个 AI 可以调用的 API 端点**。

传统 Web 开发中，你定义一个 API 端点：它有路径、请求参数、处理函数和响应格式。AI 不通过 HTTP 调用你的端点——它通过模型内部的 Function Calling 机制调用——但概念是完全平行的：

| API 端点概念 | Harness 工具概念 | 说明 |
|---|---|---|
| HTTP 路径 + 方法 | `name` | AI 看到的名字 |
| OpenAPI 请求 Schema | `parameters` | 参数定义（JSON Schema） |
| 路由处理函数 | `execute` | 实际执行的代码 |
| 响应 Schema + 渲染 | `output` | 返回值定义 + 渲染方式 |

Harness 把一个工具拆成 **四个要素**，每个都有明确的职责：

**要素一：`name`（名字）**

这是 AI 看到的工具名。AI 会读到这个名字，然后决定"当前场景下是否该调用它"。名字应该清晰、自解释。例如 `greet`、`read_file`、`web_search`，而不是 `f1`、`my_tool_42`。

系统提示词中对这块的描述是自动组装的——你注册工具后，Harness 会自动把 name、description 和 parameters 拼接到发给模型的系统提示中，你不需要手动管理。

**要素二：`parameters`（参数定义）**

这是 JSON Schema 格式的参数描述，告诉 AI："要我执行这个函数，你需要提供这些参数，每个参数是什么类型。"

参数定义包含每个字段的 `type`、`required`（是否必填）和 `description`（描述）。`description` 不是可选项——AI 通过描述来理解每个参数的含义，没有好的描述，AI 会猜错。

**要素三：`execute`（执行函数）**

这是工具的核心逻辑——收到参数后实际执行的函数。它接受 `args`（来自 AI 的参数，已经经过类型校验）和 `exec`（执行上下文，包含取消信号等），返回一个 Promise。

这个函数能做任何事情：读文件、发网络请求、执行 Shell 命令、查询数据库。只要你的插件有对应的能力（通过 `inject` 声明依赖），都能在 `execute` 里调用。

**要素四：`output`（返回值定义 + 渲染）**

返回值有两个独立的概念：

- `output.schema` — 规定返回值应该是什么结构。它是一个 JSON Schema，和参数一样是类型化的。也可以不限制结构（用自由 JSON）。
- `output.render` — 把结构化的返回值"翻译"成 AI 能读懂的自然语言文本。AI 不直接看返回值对象——它看到的是 render 函数输出的文本内容。

你可能会问：为什么不直接让 AI 看返回值 JSON 就行了？因为 JSON 的结构化信息对 AI 来说不友好。一个包含 100 个文件的统计结果用 JSON 表达可能很精确，但 AI 很难一眼看出"总共有多少行代码"——render 函数可以提取关键信息，用自然语言告诉 AI。

> **设计思路**：`execute` 返回的数据是给**程序**消费的（可以被其他插件或脚本复用），`render` 输出的文本是给 **AI 模型** 消费的（用于理解结果）。把"机器读"和"模型读"分开，是 Harness 工具设计中一个重要的抽象。

好了，四个要素都说完了。在代码层面上，它们被封装在一个叫 `defineTool` 的函数中。这个函数来自 `@deepseek-ai/dsh-tools` 包，它的作用是帮你做三件事：

1. **类型推导** — 根据你定义的 `parameters` 自动推导 `args` 的类型，让 `execute` 中拿到的是类型安全的参数
2. **参数校验** — 在 `execute` 运行之前，自动校验 AI 传来的参数是否符合 schema，类型不对、缺少必填字段、枚举值不匹配等都会自动拒绝
3. **统一包装** — 把 schema、输出声明、执行函数打包成 `ToolDefinition`，给注册表使用

现在用代码看看四个要素长什么样。

## 4.2 Hello World：greet 工具

### 场景

我们想要一个非常简单的工具：AI 可以调用它以名字问候某人，就像在说"Hey, 我叫张三"，工具回答"你好，张三！"。

### 创建插件目录

沿用第 2 章的 `scratch-plugin` 目录结构：

```
scratch-plugin/
├── src/
│   └── my-plugin.ts
└── cordis.yml
```

如果你没有保留第 2 章的目录，重新创建一份。`cordis.yml` 的内容应该像这样：

```yaml
name: scratch-plugin
version: 0.1.0
scripts:
  - src/my-plugin.ts
```

现在把 `src/my-plugin.ts` 替换为完整的 greet 工具代码：

### 完整代码

```ts
// scratch-plugin/src/my-plugin.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

// 1. 声明插件元数据和依赖
export const name = 'greet-tool'
export const inject = ['tools']

// 2. 插件入口：注册 greet 工具
export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    // 要素一：name — AI 看到的工具名
    name: 'greet',
    // description — AI 看到的工具描述
    description: 'Greet someone by name and return a friendly message.',

    // 要素二：parameters — AI 需要提供的参数
    parameters: {
      name: {
        type: 'string',
        required: true,
        description: 'The name of the person to greet',
      },
      style: {
        type: 'string',
        description: 'Greeting style: "casual" or "formal" (default: casual)',
      },
    },

    // 要素四（前半段）：output — 返回值结构声明
    output: {
      schema: {
        type: 'object',
        properties: {
          greeting: { type: 'string' },
          timestamp: { type: 'string' },
        },
        // 显式声明允许额外属性（JSON Schema 要求）
        additionalProperties: false,
      },
      // render — 将规范值转为 AI 看到的文本
      render: (_args, value) => {
        const v = value as { greeting: string; timestamp: string }
        return [{ type: 'text', text: `${v.greeting}\n(At ${v.timestamp})` }]
      },
    },

    // 要素三：execute — 实际执行函数
    async execute(args) {
      // args 已经被自动校验过类型了
      // args.style 是可选的，可能为 undefined
      const prefix = args.style === 'formal' ? 'Dear' : 'Hello'
      const greeting = `${prefix}, ${args.name}!`
      const timestamp = new Date().toISOString()
      return { greeting, timestamp }
    },
  }))
}
```

### 逐行解释关键部分

`export const inject = ['tools']` 这一行告诉 Cordis 的依赖注入系统："这个插件启动之前，先确保 `tools` 服务已经就绪。"`tools` 服务就是工具注册表——你把工具注册到它上面，AI 才能看到。

`ctx.tools.register(defineTool({...}))` 做了两件事：`defineTool` 根据你提供的信息创建一个类型安全的工具定义，`ctx.tools.register` 把这个定义注册到注册表中。注册返回一个 dispose 函数——当插件被卸载或热替换时，工具会自动注销。这个生命周期管理是自动的，不需要你手动处理。

`defineTool` 中的 `parameters` 通过一个 Map 定义：键是参数名，值是类型描述。`required: true` 表示这个参数是必填的，AI 调用时必须提供。没有 `required: true` 的属性就是可选的——AI 可以提供也可以不提供。

`execute` 函数的返回值必须匹配 `output.schema` 中声明的结构。这里我们声明了一个包含 `greeting` 和 `timestamp` 的 object，`execute` 就返回这个结构。`defineTool` 会自动校验返回值是否符合 schema——不符合会抛出 `ToolOutputError`。

`output.render` 把结构化数据渲染成一段纯文本。AI 看到的是 `render` 返回的文本内容，而不是原始的 JSON 对象。这就是前面说的"规范值 vs 渲染输出"——execute 返回构造化的 JSON，render 把它变成模型友好的文字。

### 注册工具的代码骨架

任何时候你写一个新工具，代码结构都是一样的。这就是骨架：

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = '<plugin-name>'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: '<tool-name>',
    description: '<what-the-model-sees>',
    parameters: { /* ... */ },
    output: {
      schema: { /* ... */ },
      render: (args, value) => [{ type: 'text', text: String(value) }],
    },
    async execute(args) {
      // your logic here
    },
  }))
}
```

记住这个骨架——你后面写的每个工具都会从它开始。

### 运行并测试

启动 Harness Web UI 并挂载你的插件：

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

打开 `http://127.0.0.1:3080`，在对话框中输入：

> Use the greet tool to greet Ada in a casual style.

模型应该会调用 `greet` 工具，参数为 `{ name: "Ada", style: "casual" }`，然后返回类似以下的内容：

```
Hello, Ada!
(At 2026-08-29T10:30:00.000Z)
```

再试一次正式风格：

> Greet Dr. Smith formally. Use the greet tool.

模型应该会调用 `{ name: "Dr. Smith", style: "formal" }`，返回：

```
Dear, Dr. Smith!
(At 2026-08-29T10:30:15.000Z)
```

如果模型没有自动调用工具，可以提示得更明确——上面加引号的问句已经包含了关键信息。模型一定会看到 `greet` 工具的定义（name、description、parameters），它会自己判断当前任务是否需要调用。

> **本节小结**：你写出了一个完整的工具插件，包含四个要素：name、parameters、execute、output。你在 Web UI 中看到了 AI 主动调用你的代码。

## 4.3 参数定义详解

4.2 节的 `greet` 只用了 `string` 类型和一个可选参数。定义一个复杂工具的输入参数时，你经常需要更多类型。`parameters` 使用统一的 JSON Schema DSL，支持以下数据类型。

### 字符串（string）

最基本的类型，用于名字、路径、代码片段等文本数据。

```ts
parameters: {
  path: {
    type: 'string',
    required: true,
    description: 'Absolute file path',
  },
  encoding: {
    type: 'string',
    description: 'File encoding, defaults to utf-8',
  },
}
```

### 数字（number / integer）

`number` 是浮点数，`integer` 是整数。

```ts
parameters: {
  count: {
    type: 'integer',
    required: true,
    description: 'Number of items to return',
  },
  ratio: {
    type: 'number',
    description: 'Compression ratio between 0 and 1',
  },
}
```

### 布尔值（boolean）

用于开关类型的参数。

```ts
parameters: {
  recursive: {
    type: 'boolean',
    description: 'Search recursively (default: false)',
  },
  verbose: {
    type: 'boolean',
    description: 'Print detailed output',
  },
}
```

### 数组（array）

`array` 可以进一步用 `items` 约束元素类型。

```ts
parameters: {
  files: {
    type: 'array',
    required: true,
    description: 'List of file paths to process',
    items: { type: 'string' },
  },
  ports: {
    type: 'array',
    description: 'Port numbers to scan',
    items: { type: 'integer' },
  },
}
```

### 对象（object）

嵌套对象支持结构化参数。嵌套对象必须声明 `additionalProperties` 的值（`true` 或 `false`），这是 DSL 的硬性要求。

```ts
parameters: {
  user: {
    type: 'object',
    required: true,
    description: 'User information',
    additionalProperties: false,
    properties: {
      id: { type: 'integer' },
      name: { type: 'string' },
      role: { type: 'string' },
    },
  },
}
```

### 枚举值（联合类型 / enum）

当参数只能取少数几个值时，可以使用 `enum` 约束。更复杂的场景可以用 `oneOf`（看 4.4 节）。

```ts
parameters: {
  format: {
    type: 'string',
    description: 'Output format',
    enum: ['json', 'yaml', 'text'],
  },
  level: {
    type: 'string',
    required: true,
    enum: ['debug', 'info', 'warn', 'error'],
    description: 'Log level',
  },
}
```

### 综合示例

实际工具经常混合使用多种类型。下面这个参数定义描述了一个"搜索文件内容"工具的输入：

```ts
parameters: {
  pattern: {
    type: 'string',
    required: true,
    description: 'Regular expression to search for',
  },
  path: {
    type: 'string',
    description: 'Directory to search (default: workspace root)',
  },
  include: {
    type: 'string',
    description: 'File glob filter, e.g. "*.ts"',
  },
  maxResults: {
    type: 'integer',
    description: 'Max results to return (default: 100)',
  },
  caseSensitive: {
    type: 'boolean',
    description: 'Case-sensitive search (default: true)',
  },
}
```

注意这里只有 `pattern` 是必填的——大多数情况下，搜索关键字是必需的，其他都有合理的默认值。

> **设计建议**：定义参数时，问自己两个问题：AI 最可能需要提供什么？（设为 required）。AI 大概率会传递什么值？（设为可选但推荐，因为 AI 不传会得到合理的默认行为）。好的参数设计让 AI 更容易正确调用你的工具。

> **本节小结**：你学会了 `parameters` 中所有支持的参数类型（string、number、boolean、array、object、enum），以及如何声明必填和可选参数。

## 4.4 返回值：规范值 vs 渲染输出

这是 Harness 工具设计中一个容易混淆的概念。两个词先记清楚：

- **规范值（Structured Value）** — `execute` 返回的 JSON 对象。它是**程序可读**的，可以序列化、持久化、被其他工具复用
- **渲染输出（Render Output）** — `render` 函数返回的文本内容块。它是**AI 可读**的，发给模型展示结果的关键信息

### 为什么需要区分

假设你写了一个文件统计工具（4.5 节会完整实现），它返回：

```json
{
  "totalFiles": 42,
  "totalLines": 8750,
  "byExtension": {
    ".ts": { "files": 20, "lines": 4500 },
    ".css": { "files": 10, "lines": 1250 },
    ".json": { "files": 12, "lines": 3000 }
  }
}
```

这是规范的 JSON 结构——精确、结构化、机器可读。但 AI 看到这个 JSON 有几个问题：

1. AI 需要从中"提取"关键信息——比如"哪个文件最多"它得自己算
2. JSON 嵌套深了，AI 的注意力容易分散
3. 如果有不同的工具要消费这个结果，解析固定 schema 比解析自然语言可靠得多

所以 Harness 要求你写一个 `render` 函数，把这个 JSON 转成一段自然语言：

```
Found 42 files with 8750 lines total.
- TypeScript (.ts): 20 files, 4500 lines
- CSS (.css): 10 files, 1250 lines
- JSON (.json): 12 files, 3000 lines
```

AI 现在看到的是友好的摘要，不需要自己从 JSON 里解析数字。

### 代码示例：同时定义 schema 和 render

下面这个工具演示了规范值和渲染输出如何配合。它是一个简单的"计算器"工具——AI 拿结构化的计算结果，render 输出翻译成友好消息。

```ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'calc-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'calculate',
    description: 'Perform arithmetic and return the result',

    parameters: {
      a: { type: 'number', required: true, description: 'First number' },
      b: { type: 'number', required: true, description: 'Second number' },
      operator: {
        type: 'string',
        required: true,
        enum: ['add', 'subtract', 'multiply', 'divide'],
        description: 'Arithmetic operation',
      },
    },

    // output.schema 声明返回结构
    output: {
      schema: {
        type: 'object',
        properties: {
          result: { type: 'number' },
          operation: { type: 'string' },
          expression: { type: 'string' },
        },
        additionalProperties: false,
      },

      // output.render 将结构值转为文本
      render: (_args, value) => {
        const v = value as {
          result: number
          operation: string
          expression: string
        }
        return [{
          type: 'text',
          text: `The result of "${v.expression}" is **${v.result}** (operation: ${v.operation}).`,
        }]
      },
    },

    async execute(args) {
      let result: number
      switch (args.operator) {
        case 'add':      result = args.a + args.b; break
        case 'subtract': result = args.a - args.b; break
        case 'multiply': result = args.a * args.b; break
        case 'divide':
          if (args.b === 0) throw new Error('Division by zero')
          result = args.a / args.b; break
      }
      return {
        result,
        operation: args.operator,
        expression: `${args.a} ${operatorSymbol(args.operator)} ${args.b}`,
      }
    },
  }))
}

function operatorSymbol(op: string): string {
  const map: Record<string, string> = {
    add: '+', subtract: '-', multiply: '×', divide: '÷',
  }
  return map[op] ?? op
}
```

这个例子中，`execute` 返回的结果包含三个字段：计算结果、操作名、表达式。`render` 把它们组合成一句自然语言。AI 得到的是类似这样的内容：

```
The result of "3 × 7" is **21** (operation: multiply).
```

### render 函数的签名

`render` 的完整签名是 `(args: unknown, value: JsonValue) => ContentBlock[]`。它接收两个参数：

- `args` — AI 调用时传的参数，如果你需要在渲染时引用原始输入（比如"你刚才问我 3 × 7，答案是 21"），可以从这里拿到
- `value` — `execute` 返回的规范值（已经经过校验和冻结）

返回值是一个 `ContentBlock[]`。大多数情况下你只需要返回包含一个 `{ type: 'text', text: '...' }` 的数组。但你也可以返回多个块，比如同时包含文本和图片引用的结果。

### 最佳实践

- `execute` 返回**结构化数据**：字段名清晰、类型一致、可被程序安全使用
- `render` 输出**摘要信息**：提取关键字段，用自然语言组织，供 AI 理解
- `render` 必须是**纯函数**：它可能在实时执行和会话回放时被调用，不能做 I/O、不能用时钟/随机数
- 不要把 UI 格式塞进规范值：比如 `"```console"` 围栏代码块是 render 或 UI 的工作，不是规范值该干的事

> **本节小结**：你理解了规范值和渲染输出的区别。`execute` 返回结构化 JSON，`render` 把它转为 AI 看得懂的文本。这个分离让工具既可程序化复用，又对 AI 友好。

## 4.5 实际案例：文件统计工具

现在让我们写一个真正有用的工具。

### 场景

AI 需要统计一个 TypeScript 项目中的代码量：总文件数、总行数、按后缀名分类的明细。这些信息在项目规模估算、代码审查、重构前评估时很有用。

### 需求分析

1. AI 传入一个目录路径
2. 可选地指定要统计的文件扩展名（默认统计全部）
3. 工具递归遍历目录下的所有文件
4. 统计每个文件的代码行数
5. 返回：总文件数、总行数、每类文件的明细

这是 4.4 节"规范值 vs 渲染输出"理论的最佳应用场景——返回结构化的统计数据，同时渲染一段摘要给 AI。

### 完整代码

```ts
// scratch-plugin/src/file-stats.ts
import { readFileSync, readdirSync, statSync } from 'node:fs'
import { join, extname } from 'node:path'
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'file-stats-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'file_stats',
    description: 'Count lines of code in a directory. Returns total files, total lines, and per-extension breakdown.',

    parameters: {
      path: {
        type: 'string',
        required: true,
        description: 'Absolute path to the directory to analyze',
      },
      extensions: {
        type: 'array',
        description: 'File extensions to include, e.g. [".ts", ".js"]. Omit to count all files.',
        items: { type: 'string' },
      },
      excludeDirs: {
        type: 'array',
        description: 'Directory names to skip, e.g. ["node_modules", "dist"]. Defaults to common ignore dirs.',
        items: { type: 'string' },
      },
    },

    output: {
      schema: {
        type: 'object',
        properties: {
          totalFiles: { type: 'integer' },
          totalLines: { type: 'integer' },
          byExtension: {
            type: 'object',
            additionalProperties: true,
            properties: {},
          },
          targetPath: { type: 'string' },
          truncated: { type: 'boolean' },
        },
        additionalProperties: false,
      },

      render: (_args, value) => {
        const v = value as {
          totalFiles: number
          totalLines: number
          byExtension: Record<string, { files: number; lines: number }>
          targetPath: string
        }
        const lines = [`## File Stats for ${v.targetPath}`]
        lines.push(`**Total:** ${v.totalFiles} files, ${v.totalLines} lines`)
        lines.push('')
        lines.push('| Extension | Files | Lines |')
        lines.push('|-----------|-------|-------|')
        // 按行数降序排列，最多的排最前面
        const sorted = Object.entries(v.byExtension)
          .sort(([, a], [, b]) => b.lines - a.lines)
        for (const [ext, stat] of sorted) {
          const extLabel = ext || '(no extension)'
          lines.push(`| ${extLabel} | ${stat.files} | ${stat.lines} |`)
        }
        return [{ type: 'text', text: lines.join('\n') }]
      },
    },

    async execute(args) {
      const root = args.path
      const includeExts = args.extensions?.length
        ? new Set(args.extensions.map((e: string) => e.startsWith('.') ? e : `.${e}`))
        : null
      const skipDirs = new Set(
        args.excludeDirs?.length
          ? args.excludeDirs
          : ['node_modules', 'dist', '.git', '.next', 'build', 'coverage'],
      )

      const byExt: Record<string, { files: number; lines: number }> = {}
      let totalFiles = 0
      let totalLines = 0
      let truncated = false
      const MAX_FILES = 500

      // 递归遍历目录
      function walk(dir: string) {
        if (totalFiles >= MAX_FILES) {
          truncated = true
          return
        }

        let entries: string[]
        try { entries = readdirSync(dir) } catch {
          return // 无权限的目录直接跳过
        }

        for (const entry of entries) {
          if (totalFiles >= MAX_FILES) {
            truncated = true
            return
          }

          const fullPath = join(dir, entry)

          let st
          try { st = statSync(fullPath) } catch {
            continue // 符号链接损坏等情况直接跳过
          }

          if (st.isDirectory()) {
            if (!skipDirs.has(entry)) walk(fullPath)
          } else if (st.isFile()) {
            const ext = extname(fullPath)
            if (includeExts && !includeExts.has(ext)) continue

            totalFiles++
            let lines = 0
            try {
              const text = readFileSync(fullPath, 'utf-8')
              lines = text.split('\n').length
            } catch {
              // 二进制文件或编码问题，行数记为 0
              lines = 0
            }
            totalLines += lines

            if (!byExt[ext]) byExt[ext] = { files: 0, lines: 0 }
            byExt[ext].files++
            byExt[ext].lines += lines
          }
        }
      }

      walk(root)

      return {
        totalFiles,
        totalLines,
        byExtension: byExt,
        targetPath: root,
        truncated,
      }
    },
  }))
}
```

### 代码要点说明

**同步文件操作**：这个工具中我们用的是 `readFileSync` 和 `readdirSync`，而不是 `fs/promises` 的异步版本。原因是 `execute` 本身就是一个 async 函数，内部用同步 API 让代码更清晰简单，不需要处理并发遍历带来的竞态问题。

**`byExtension` 结构**：工具返回的结果按扩展名分组。`".ts"`、`".js"`、`".css"` 各为一个键，值是一个包含 `files` 和 `lines` 的子对象。render 函数按行数降序排列后生成 Markdown 表格。

**错误容忍**：遍历过程中遇到无权限访问的目录、损坏的符号链接、二进制文件等，都直接跳过而不是抛出异常，保证工具至少能返回部分结果。

**截断保护**：通过 `MAX_FILES = 500` 限制最大遍历文件数，防止 AI 误传入根目录导致长时间无响应。`truncated` 字段告知 AI 结果是不完整的。

### 注册文件统计工具

你需要在 `cordis.yml` 中注册这个新文件。编辑 `scratch-plugin/cordis.yml`：

```yaml
name: scratch-plugin
version: 0.1.0
scripts:
  - src/greet.ts
  - src/file-stats.ts
```

或者你也可以把两个工具放在同一个文件中（比如 `my-plugin.ts`，把 `file-stats.ts` 的 `apply` 函数并进去）。不过分开文件更清晰——后面添加新工具时只要追加新文件就行。

> **注意**：如果你选择分开文件，每个文件都需要独立的 `name` 和 `apply`。Cordis 会把同一插件目录下多个文件中导出的 `name`/`apply` 都视为同一个插件下的不同入口点。实际上更推荐的写法是把所有工具放在一个 `apply` 中注册，避免歧义。我们会在 4.7 节给出最终的文件结构。

## 4.6 在 Web UI 中测试

工具写完了，运行它并亲眼看到 AI 调用它。

### 启动 Web UI

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

打开浏览器访问 `http://127.0.0.1:3080`。

### 测试 greet 工具

输入以下对话：

> Can you greet me? My name is Xiao Ming.

模型应当识别出这是一个"问候"场景，调用 `greet` 工具。如果你看到类似下面的输出，说明工具生效了：

```
Hello, Xiao Ming!
(At 2026-08-29T14:30:00.000Z)
```

如果模型没有自动调用，换一种更直接的提示：

> Use the greet tool to greet "Ada". Use casual style.

模型在决策是否调用工具时，会读工具的名字（`greet`）和描述（"Greet someone by name and return a friendly message."）。只要提示词中有明确的意图，模型通常会触发工具调用。

### 测试文件统计工具

选择一个你有 TypeScript 代码的项目目录做测试。假设你的 Harness 仓库在 `/workspace/harness`：

> Use the file_stats tool to count lines of code in /path/to/some/typescript/project. Only count .ts files and skip node_modules.

如果工具正确执行，AI 应该看到类似这样的结果：

```
## File Stats for /path/to/some/typescript/project
**Total:** 45 files, 8750 lines

| Extension | Files | Lines |
|-----------|-------|-------|
| .ts | 30 | 6500 |
| .tsx | 10 | 1500 |
| .json | 5 | 750 |
```

如果路径不存在或无权限访问，AI 会收到一个错误结果。此时可以尝试让 AI 换个路径再试——它不是程序错误，只是路径不对。

### 调试技巧

工具不按预期工作时，用以下方法排查：

**console.log**

在 `execute` 函数中加 `console.log`：

```ts
async execute(args) {
  console.log('[file_stats] called with:', JSON.stringify(args))
  // ... rest of logic
}
```

日志会打印在启动 Harness 的终端窗口中。注意不要在生产工具中留调试日志。

**错误处理**

如果工具的 execute 抛出异常，Harness 会自动捕获并返回一个 `isError: true` 的结果给 AI。检查一下抛出的错误信息是否对 AI 友好——"Cannot read property 'x' of undefined" 这类信息对 AI 完全没有帮助。更好的做法是提前校验参数并抛出有意义的错误：

```ts
async execute(args) {
  if (!args.path) {
    throw new Error('path is required but was not provided')
  }
  // ... rest
}
```

**观察工具执行日志**

在 Web UI 中，工具调用和结果都会显示为 UI 卡片。你可以看到：

1. AI 选择了哪个工具
2. 传入了什么参数
3. 工具返回了什么结果（包含渲染后的内容）

如果工具返回了错误，卡片上也会显示错误信息。

> **本节小结**：你在 Web UI 中成功测试了两个工具——greet 和 file_stats。你学会了通过 UI 卡片观察工具的执行过程，也掌握了 console.log 和错误处理的基本调试方法。

### 推荐写法：统一的入口文件

上面我们用了两个独立的文件（`greet.ts` 和 `file-stats.ts`），但在实际项目中，更好的实践是**一个插件一个入口文件**，统一注册所有工具。这样做的好处是依赖关系清晰、注册顺序可控。

创建 `scratch-plugin/src/index.ts`，合并两个工具：

```ts
// scratch-plugin/src/index.ts
import { readFileSync, readdirSync, statSync } from 'node:fs'
import { join, extname } from 'node:path'
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'scratch-plugin'
export const inject = ['tools']

export function apply(ctx: Context) {
  // ======== greet 工具 ========
  ctx.tools.register(defineTool({
    name: 'greet',
    description: 'Greet someone by name and return a friendly message.',
    parameters: {
      name: { type: 'string', required: true, description: 'The name to greet' },
      style: {
        type: 'string',
        description: 'casual or formal (default: casual)',
        enum: ['casual', 'formal'],
      },
    },
    output: {
      schema: {
        type: 'object',
        properties: {
          greeting: { type: 'string' },
          timestamp: { type: 'string' },
        },
        additionalProperties: false,
      },
      render: (_args, value) => {
        const v = value as { greeting: string; timestamp: string }
        return [{ type: 'text', text: `${v.greeting}\n(At ${v.timestamp})` }]
      },
    },
    async execute(args) {
      const prefix = args.style === 'formal' ? 'Dear' : 'Hello'
      return {
        greeting: `${prefix}, ${args.name}!`,
        timestamp: new Date().toISOString(),
      }
    },
  }))

  // ======== file_stats 工具 ========
  ctx.tools.register(defineTool({
    name: 'file_stats',
    description: 'Count lines of code in a directory. Returns total files, total lines, and per-extension breakdown.',
    parameters: {
      path: {
        type: 'string', required: true,
        description: 'Absolute path to the directory to analyze',
      },
      extensions: {
        type: 'array', items: { type: 'string' },
        description: 'Extensions to include, e.g. [".ts", ".js"]. Omit to count all files.',
      },
      excludeDirs: {
        type: 'array', items: { type: 'string' },
        description: 'Directory names to skip. Defaults to node_modules, dist, .git, etc.',
      },
    },
    output: {
      schema: {
        type: 'object',
        properties: {
          totalFiles: { type: 'integer' },
          totalLines: { type: 'integer' },
          byExtension: { type: 'object', additionalProperties: true, properties: {} },
          targetPath: { type: 'string' },
          truncated: { type: 'boolean' },
        },
        additionalProperties: false,
      },
      render: (_args, value) => {
        const v = value as {
          totalFiles: number; totalLines: number
          byExtension: Record<string, { files: number; lines: number }>
          targetPath: string
        }
        const rows = [`## File Stats for ${v.targetPath}`]
        rows.push(`**Total:** ${v.totalFiles} files, ${v.totalLines} lines\n`)
        rows.push('| Extension | Files | Lines |')
        rows.push('|---|---|---|')
        const sorted = Object.entries(v.byExtension).sort(([, a], [, b]) => b.lines - a.lines)
        for (const [ext, s] of sorted) {
          rows.push(`| ${ext || '(none)'} | ${s.files} | ${s.lines} |`)
        }
        return [{ type: 'text', text: rows.join('\n') }]
      },
    },
    async execute(args) {
      const root = args.path
      const includeExts = args.extensions?.length
        ? new Set(args.extensions.map((e: string) => e.startsWith('.') ? e : `.${e}`))
        : null
      const skipDirs = new Set(
        args.excludeDirs?.length
          ? args.excludeDirs
          : ['node_modules', 'dist', '.git', '.next', 'build', 'coverage'],
      )
      const byExt: Record<string, { files: number; lines: number }> = {}
      let totalFiles = 0, totalLines = 0, truncated = false
      const MAX = 500

      function walk(dir: string) {
        if (totalFiles >= MAX) { truncated = true; return }
        let entries: string[]
        try { entries = readdirSync(dir) } catch { return }
        for (const entry of entries) {
          if (totalFiles >= MAX) { truncated = true; return }
          const fp = join(dir, entry)
          let st
          try { st = statSync(fp) } catch { continue }
          if (st.isDirectory()) {
            if (!skipDirs.has(entry)) walk(fp)
          } else if (st.isFile()) {
            const ext = extname(fp)
            if (includeExts && !includeExts.has(ext)) continue
            totalFiles++
            let lines = 0
            try {
              const text = readFileSync(fp, 'utf-8')
              lines = text.split('\n').length
            } catch { lines = 0 }
            totalLines += lines
            if (!byExt[ext]) byExt[ext] = { files: 0, lines: 0 }
            byExt[ext].files++
            byExt[ext].lines += lines
          }
        }
      }

      walk(root)
      return { totalFiles, totalLines, byExtension: byExt, targetPath: root, truncated }
    },
  }))
}
```

对应的 `cordis.yml`：

