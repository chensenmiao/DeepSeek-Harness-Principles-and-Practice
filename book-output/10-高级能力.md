## 8.1 Subagent

### Subagent 是什么

Subagent（子智能体）让一个 Agent 将工作委派给子 Agent，实现任务的拆分与并行处理。与普通工具调用不同，Subagent 拥有独立的会话上下文、工具集和模型调用权限，是一个完整独立的"子大脑"。Subagent 的能力是可选的，不属于 Agent 核心循环。

### Subagent 提供方

Harness 内置了多个 Subagent 提供方，通过 `ctx.subagents` 命名注册表管理：

| 提供方名称 | 包 | 说明 |
|---|---|---|
| `spawn` | dsh-subagent-spawn-in-process | 进程内启动，子 Agent 使用独立的会话上下文 |
| `fork` | dsh-subagent-fork-in-process | 进程内启动，继承父 Agent 的对话历史 |
| `acp` | dsh-subagent-acp | 远程 ACP 协议子 Agent |

多个提供方可以在同一上下文中共存，按名称注册和调用。

### 在插件中调用 Subagent

在插件中，你可以使用 `ctx.subagents` 服务启动一次性子 Agent。以下示例演示如何创建一个 fork 类型的子 Agent：

```typescript
import { Context } from '@deepseek-ai/cordis'
import type { SubagentStartRequest } from '@deepseek-ai/dsh-subagent'

export const inject = ['subagents']

export function apply(ctx: Context) {
  ctx.on('some/event', async (parentAgent) => {
    // 构造子 Agent 请求
    const request: SubagentStartRequest = {
      label: '代码审查助手',
      prompt: [{ type: 'text', text: '请审查以下代码并列出问题：...' }],
      parent: parentAgent,
      signal: new AbortController().signal,
    }

    // 启动一次性子 Agent（fork 提供方，继承父 Agent 上下文）
    const run = await ctx.subagents.start('fork', request)

    // 等待子 Agent 完成，获取结果
    const result = await run.result
    console.log('子 Agent 输出:', result.output)

    // 务必释放资源
    await run.dispose()
  })
}
```

### 可继续子 Agent

可继续（continuable）子 Agent 是持久化的子会话，支持多轮对话。使用 `startContinuable()` 创建：

```typescript
// 创建一个可继续子 Agent
const { childId } = await ctx.subagents.startContinuable({
  provider: 'spawn',
  label: '数据收集助手',
  prompt: [{ type: 'text', text: '请开始分析数据集...' }],
  parent: parentAgent,
  signal: signal,
})

// 后续轮次跟进
const msgId = await ctx.subagents.followup(
  parentAgent,
  childId,
  [{ type: 'text', text: '继续，再给我更详细的数据' }],
  { source: { kind: 'user' }, signal: signal }
)
```

### 父子 Agent 通信

可继续子 Agent 可以通过 `reportFrom()` 向父 Agent 发送报告，而父 Agent 可以通过 `interrupt()` 中断子 Agent 的当前轮次：

```typescript
// 子 Agent 内部报告
await ctx.subagents.reportFrom(
  childAgent,
  [{ type: 'text', text: '任务完成 50%，遇到了一个异常数据点...' }],
  { delivery: 'next-step', signal: signal }
)

// 父 Agent 中断子 Agent
ctx.subagents.interrupt(childId, {
  kind: 'ancestor',
  agent: parentAgent,
})
```

### Agent Team：多 Agent 团队

Agent Team（实验性功能）通过 `ctx.agentTeams` 提供了多 Agent 协作的能力，包括团队成员管理、持久化的消息邮箱（mailbox）和共享任务 DAG。

```typescript
export const inject = ['agentTeams']

export function apply(ctx: Context) {
  // 创建团队成员
  ctx.someCommand(async (agent) => {
    const member = await ctx.agentTeams.spawnTeammate(agent, {
      name: '数据分析师',
      description: '负责数据清洗和统计分析',
      prompt: [{ type: 'text', text: '你是一名数据分析师...' }],
      context: 'fresh',
      provider: 'spawn',
    })

    // 向团队成员发送消息
    await ctx.agentTeams.sendMessage(agent, {
      targetName: '数据分析师',
      content: [{ type: 'text', text: '请分析附件中的数据集' }],
      delivery: 'wakeup',
    })

    // 创建共享任务
    await ctx.agentTeams.createTask(agent, {
      subject: '清洗数据',
      description: '去除空值和异常值',
      blockedBy: [],
      writeScopes: ['data/'],
    })
  })
}
```

## 8.2 Goal 系统

### Goal 是什么

Goal 是持久化的任务跟踪系统，用于在长时间的多轮对话中追踪目标进度。它支持暂停、恢复、阻塞和完成等生命周期状态。

Goal 的状态机包含四个持久阶段：

- `active`：激活中，Agent 正在朝目标推进
- `paused`：暂停，自动续跑已关闭
- `blocked`：阻塞，携带阻塞原因
- `complete`：已完成

### Goal Round 的概念

Goal Round（目标轮次）是 Agent 每轮消息的编号标记。每个被准入的用户消息轮次都会标注正数且连续的 Round 编号，用于追踪 Agent 为达成目标花了多少轮。通过 `maxGoalRounds` 可以控制最大轮次上限。

### ctx.goals 服务

插件通过 `ctx.goals` 服务来创建、编辑和管理目标：

```typescript
import { Context } from '@deepseek-ai/cordis'

export const inject = ['goals']

export function apply(ctx: Context) {
  ctx.on('some/trigger', async (agent) => {
    // 创建目标
    const goal = ctx.goals.create(agent, {
      objective: '完成用户画像分析报告，包含年龄分布、地域分布和消费习惯三个维度',
      maxGoalRounds: 15,
    })
    console.log('目标已创建，ID:', goal.id)

    // 读取当前目标
    const current = ctx.goals.get(agent)
    if (current) {
      console.log('阶段:', current.phase)
      console.log('已开始轮次:', current.roundsStarted)
    }

    // 暂停目标
    ctx.goals.pause(agent, { id: goal.id, revision: goal.revision })

    // 恢复目标
    const resumed = ctx.goals.resume(agent, { id: goal.id, revision: /* 最新 revision */ })

    // 标记为阻塞
    ctx.goals.block(agent, resumed, {
      code: 'waiting-for-data',
      message: '等待业务方提供最新的用户数据',
    })

    // 标记完成
    ctx.goals.complete(agent, { id: goal.id, revision: /* 最新 revision */ })
  })
}
```

### 场景：多轮对话完成复杂任务

Goal 最典型的应用场景是让 Agent 在多个轮次中逐步完成复杂任务：

```typescript
// 插件监听 goal/changed 事件，在目标状态变化时做出响应
ctx.on('goal/changed', ({ agent, change }) => {
  if (change.goal?.phase === 'blocked') {
    // 目标阻塞时，触发外部流程（如通知用户）
    notifyUser(`目标 ${change.goal.objective} 阻塞：${change.goal.blockedReason?.message}`)
  }

  if (change.goal?.phase === 'complete') {
    // 目标完成，执行后续处理
    onGoalComplete(agent, change.goal)
  }
})
```

## 8.3 Workflow 引擎

### 工作流引擎 vs 手动编排

Workflow 引擎允许 Agent 运行由模型编写的编排脚本，脚本中可以启动多个 Subagent 并控制它们的执行顺序。与手动在插件中编排相比，Workflow 引擎提供：

- **并行执行**：`parallel()` 组合子同时启动多个子 Agent
- **管道执行**：`pipeline()` 组合子按顺序传递中间结果
- **内置并发控制**：`maxTotalAgents` 上限
- **Worker 线程隔离**：脚本在独立的 worker 线程中运行

### ctx.workflowEngine 服务

```typescript
import { Context } from '@deepseek-ai/cordis'

export const inject = ['workflowEngine']

export function apply(ctx: Context) {
  ctx.on('some/trigger', async (agent) => {
    const script = `
      const analysis = await agent('分析数据', {
        prompt: '请分析这些数据的趋势',
      })

      const report = await agent('生成报告', {
        prompt: \`请基于以下分析结果生成报告：\${analysis}\`,
      })

      return report
    `

    const run = ctx.workflowEngine.start({
      script,
      meta: {
        name: 'data-analysis',
        description: '数据分析与报告生成工作流',
        phases: [
          { name: '分析', description: '数据分析阶段' },
          { name: '报告', description: '报告生成阶段' },
        ],
      },
      parent: agent,
      signal: new AbortController().signal,
    })

    // 监听工作流事件
    ctx.on('workflow/log', (info, message) => {
      console.log(`[${info.meta.name}]`, message)
    })

    ctx.on('workflow/phase', (info, title) => {
      console.log(`进入阶段: ${title}`)
    })

    // 等待结果
    const result = await run.result
    console.log('工作流完成，返回值:', result.value)

    await run.dispose()
  })
}
```

### Worker 线程与并发控制

Workflow 引擎默认使用 `node:worker_threads` 作为执行后端——每个 run 一个 worker，脚本的 vm 上下文位于其中。插件可以在启动时配置并发控制参数：

```typescript
const run = ctx.workflowEngine.start({
  script,
  meta: { name: 'heavy-task', description: '密集型任务' },
  subagentProvider: 'spawn',   // 所有子 Agent 使用 spawn 提供方
  maxTotalAgents: 10,          // 整个工作流最多启动 10 个子 Agent
  parent: agent,
})
```

## 8.4 Plan Mode

### Plan Mode 是什么

Plan Mode（计划模式）是一种软性指引。激活期间，每个模型请求都会包含一段部署配置的计划指引提示词，引导 Agent 先制定计划再执行。Plan Mode 通过 `ctx.planMode` 服务控制。

关键特性：

- 是**软性指引**，不会强制限制 Agent 行为
- 状态持久化到会话日志，支持恢复和回放
- 与沙箱模式和审批策略正交，可独立配置

### 进入/退出

```typescript
import { Context } from '@deepseek-ai/cordis'

export const inject = ['planMode']

export function apply(ctx: Context) {
  // 读取当前状态
  const status = ctx.planMode.get(agent)
  console.log('计划模式状态:', status.active)

  // 启用计划模式
  const result = ctx.planMode.set(agent, true)
  // 'committed' | 'queued' | 'cancelled' | 'noop'

  // 禁用计划模式
  ctx.planMode.set(agent, false)
}
```

### 在插件中与 Plan Mode 交互

Plan Mode 贡献 `plan:policy` 提示词段落，并注册 `exit_plan_mode` 工具和 `/plan` 命令。插件可以监听计划状态变更来调整自身行为：

```typescript
// 在插件中根据计划模式的启用以决定是否注入额外提示词
ctx.on('agent/pre-step', (agent, step) => {
  const { active } = ctx.planMode.get(agent)
  if (active) {
    // 计划模式激活时，注入额外的上下文
    step.prependSystemMessage('请严格按照当前计划执行，不要偏离。')
  }
})
```

## 8.5 Schedule 调度

### ctx.schedule 服务

Schedule 子系统提供持久化的提醒功能。提醒会在到期时作为普通的后续对话轮次（follow-up）返回原 Session。通过 `ctx.schedule` 服务管理。

支持三种调度类型：

| 类型 | 说明 | 示例 |
|---|---|---|
| `after` | 延迟一次性提醒 | 30 分钟后提醒 |
| `at` | 绝对时间点提醒 | 明天下午 3 点 |
| `every` | 固定频率重复提醒 | 每 30 分钟检查一次 |

### 一次性提醒和固定频率提醒

```typescript
import { Context } from '@deepseek-ai/cordis'

export const inject = ['schedule']

export function apply(ctx: Context) {
  ctx.on('some/event', async (agent) => {
    // 30 秒后提醒
    const afterId = await ctx.schedule.create({
      kind: 'after',
      afterSeconds: 30,
      prompt: '30 秒已到，请检查任务状态。',
    })

    // 绝对时间点提醒
    const atId = await ctx.schedule.create({
      kind: 'at',
      at: { date: '2026-09-01', time: '14:00', time_zone: 'Asia/Shanghai' },
      prompt: '下午 2 点的会议时间到了。',
    })

    // 固定频率提醒（每 5 分钟一次）
    const everyId = await ctx.schedule.create({
      kind: 'every',
      everySeconds: 300,
      prompt: '请检查是否有新的通知需要处理。',
    })

    // 查看所有提醒
    const schedules = await ctx.schedule.list()

    // 删除提醒
    await ctx.schedule.delete(everyId)
  })
}
```

### 时区处理

Schedule 使用显式时区。`at` 类型接受 RFC 3339 字符串或本地日历对象。本地日历对象需要显式指定 `time_zone`：

```typescript
// 使用 IANA 时区
await ctx.schedule.create({
  kind: 'at',
  at: {
    date: '2026-09-01',
    time: '09:00:00',
    time_zone: 'America/New_York',
  },
  prompt: '纽约股市开盘提醒。',
})

// 使用 UTC 偏移量
await ctx.schedule.create({
  kind: 'at',
  at: '2026-09-01T09:00:00+08:00',
  prompt: '北京时间上午 9 点。',
})
```

### 定时任务的持久化

Schedule 的持久化基于会话事件（`schedule/change` 事件类型）：

- `create`：保存完整记录
- `delete`：终结性仅 id 转换（一次性提醒被删除或 dispatch 后即终结）
- `dispatch`：标记已触发

触发后的提醒会作为 follow-up 消息进入原始 Session 的对话流，不会创建独立的 Web 回执。

## 8.6 其他能力

### Skill 系统：`ctx.skills`

Skill 系统提供了一个注册表，用于管理和发现 Agent 可调用的指令集（即"技能"）。插件可以通过 `ctx.skills` 注册和查询技能。

```typescript
import { Context } from '@deepseek-ai/cordis'

export const inject = ['skills']

export function apply(ctx: Context) {
  // 注册一个运行时技能
  ctx.skills.register({
    name: 'my-custom-tool',
    description: '自定义工具的详细使用说明',
    content: '# 我的自定义工具\n\n使用这个工具时，请按照以下步骤...\n\n## 注意事项\n- 步骤一：...\n- 步骤二：...',
    invocation: {
      modelInvocable: true,
      userInvocable: false,
    },
  })

  // 注册文件系统技能提供方
  ctx.skills.registerProvider((control) => ({
    name: 'my-skills',
    async list(options) {
      // 返回技能候选项列表
      return [{ name: 'deploy-guide', description: '部署指南', rank: 50, locator: 'deploy' }]
    },
    async get(candidate, options) {
      // 返回完整技能内容
      return {
        name: candidate.name,
        description: '部署指南',
        content: '# 部署指南\n\n...',
        invocation: { modelInvocable: true, userInvocable: true },
        provider: 'my-skills',
        resourceBase: { kind: 'directory', path: '/path/to/resources' },
      }
    },
  }))

  // 查询技能目录
  const skills = await ctx.skills.list({ cwd: '/project' })
  for (const skill of skills) {
    console.log(`${skill.name}: ${skill.description}`)
  }
}
```

### 命令系统：`ctx.commands`

命令系统允许插件注册用户可直接调用的斜杠命令（如 `/help`、`/plan`），命令会直接执行而无需经过模型推理。

```typescript
import { Context } from '@deepseek-ai/cordis'

export const inject = ['commands']

export function apply(ctx: Context) {
  // 注册一个命令
  ctx.commands.register({
    name: 'status',          // 用户输入 /status 触发
    description: '查看当前系统状态',
    input: { hint: '可选：模块名称' },
    handler: (invocation) => {
      const module = invocation.rawInput.trim()
      if (module) {
        return {
          kind: 'success',
          text: `模块 "${module}" 的状态：运行正常`,
        }
      }
      return {
        kind: 'success',
        text: '所有模块运行正常',
      }
    },
  })

  // 注册带图片支持的命令
  ctx.commands.register({
    name: 'analyze',
    description: '分析上传的图片',
    input: { hint: '描述分析需求', images: true },
    handler: async (invocation) => {
      // invocation.attachments 包含已准入的图片
      if (invocation.attachments.length === 0) {
        return { kind: 'error', text: '请上传图片' }
      }
      return { kind: 'success', text: `已分析 ${invocation.attachments.length} 张图片` }
    },
  })
}
```

命令之间的作用域规则：全局定义的命令对所有 Agent 可见；在 Agent 子上下文中注册的命令会遮蔽全局同名命令（scoped shadowing）。

### Slot 系统：`ctx.slots`

Slot 系统是 Web Client 的类型化 React 组合系统，允许插件向 UI 贡献自定义组件。

```typescript
import { Context } from '@deepseek-ai/cordis'
import type {} from '@deepseek-ai/dsh-client-ui-conversation/client'
import type { PropsRuntime } from '@deepseek-ai/dsh-client-ui-slots'

export const inject = ['slots']

// 组件使用 PropsRuntime 推导 props 类型
type HeaderActionProps = PropsRuntime<'conversation.session.header.actions'>

function HeaderAction({ useSession }: HeaderActionProps) {
  const running = useSession(snapshot => snapshot.running)
  return <button disabled={running}>审核</button>
}

export function apply(ctx: Context) {
  // 向已有 slot 注入 UI 组件
  ctx.slots.inject('conversation.session.header.actions', () =>
    ctx.slots.register({
      name: 'conversation.session.header.actions',
      id: 'review-action',           // 唯一标识
      order: 100,                     // 排序权重
    }, HeaderAction)
  )
}
```

Slot 的 Cardinality 类型：

| 类型 | 说明 |
|---|---|
| `single` | 单个占位，渲染优先级最高的组件 |
| `list` | 列表，按 order 排序渲染所有注册项 |
| `keyed` | 键值匹配，owner 传入 key 选择渲染 |
| `chain` | 链式选择，第一个返回非 null 结果的组件获胜 |

### Webhook 集成

Webhook 子系统通过 `ctx.webhookRuntime` 服务，将外部系统的 HTTP 回调转换为可选的普通根 Session。

```typescript
import { Context } from '@deepseek-ai/cordis'

export const inject = ['webhookRuntime']

export function apply(ctx: Context) {
  // 注册一个 webhook 规则
  const dispose = await ctx.webhookRuntime.register({
    id: 'github-pr-review',
    kind: 'github',          // 提供方种类
    run: async (delivery, signal) => {
      const event = delivery.event as any
      if (event.action === 'opened' && event.pull_request) {
        // 返回 Session 创建请求
        return {
          workspacePath: '/projects/my-app',
          title: `PR Review: ${event.pull_request.title}`,
          prompt: `请审查 PR #${event.pull_request.number}：\n\n${event.pull_request.body || ''}`,
          agentPreset: 'code-review',
          permissionPreset: 'sandboxed',
        }
      }
      return null  // 不创建 Session 的场景
    },
  })

  // 注册完成后，每当 GitHub 推送 PR opened 事件，
  // runtime 会自动创建 Session 并启动 Agent 执行代码审查
}
```

Webhook 采用 fire-and-forget 分发策略：`dispatch()` 会快照匹配规则，彼此独立调度，并在任何回调结算前返回。每个规则回调各自捕获异常，互不影响。没有内置的重试或去重机制（重复的 webhook 请求可能创建重复 Session）。

## 8.7 本章小结

本章涵盖了 DeepSeek Harness 的九大高级能力，这些能力让插件不再局限于简单的工具注册，而是可以构建复杂的多 Agent 协作、持久化任务跟踪、动态编排、用户交互和外部系统集成：

| 能力 | 核心服务 | 适用场景 |
|---|---|---|
| **Subagent** | `ctx.subagents` | 子任务委派，多 Agent 并行 |
| **Agent Team** | `ctx.agentTeams` | 多 Agent 团队协作（实验性） |
| **Goal** | `ctx.goals` | 多轮对话中的任务追踪 |
| **Workflow** | `ctx.workflowEngine` | 动态编排子 Agent 执行流程 |
| **Plan Mode** | `ctx.planMode` | 引导 Agent 先计划后执行 |
| **Schedule** | `ctx.schedule` | 定时提醒和周期性任务 |
| **Skill** | `ctx.skills` | 可发现的指令集注册与管理 |
| **Command** | `ctx.commands` | 用户可直接调用的斜杠命令 |
| **Slot** | `ctx.slots` | UI 组件扩展注入 |
| **Webhook** | `ctx.webhookRuntime` | 外部系统的回调接入 |

在设计插件时，将需要 Agent 在多个轮次中持续推进的任务交给 Goal；将需要拆分执行的复杂编排交给 Workflow；将需要与外部系统交互的场景交给 Webhook。理解这些能力的边界和注册方式，能帮助你最大化发挥 Harness 插件平台的潜力。

下一步，你将在第 9 章学习如何将这些能力组合起来，构建一个完整的端到端插件项目。
