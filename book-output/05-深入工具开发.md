## 5.1 文件系统工具

### 场景

第 4 章的 `file_stats` 工具直接用了 Node.js 的 `fs` 模块。这在实验阶段没有问题，但在生产工具中应该使用 Harness 提供的 `ctx.fs` 服务。它有几点好处：

1. **路径解析**：统一处理相对路径、工作目录、符号链接
2. **文件观测策略**：先读后写、陈旧版本检测
3. **沙箱感知**：在受限模式下自动拒绝越权操作
4. **统一错误码**：`FS_NOT_FOUND`、`FS_PERMISSION_DENIED` 等稳定分类

### 代码：一个按文件名模式搜索的工具

这个工具让 AI 通过 glob 模式搜索文件名并返回结果列表。

```ts
// scratch-plugin/src/search.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'search-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'search_files',
    description: 'Search for files by glob pattern in a directory. Returns matching file paths sorted by modification time, up to 100 results.',

    parameters: {
      pattern: {
        type: 'string',
        required: true,
        description: 'Glob pattern, e.g. "**/*.ts", "src/**/*.test.js". A pattern with no "/" matches basename at any depth.',
      },
      path: {
        type: 'string',
        description: 'Directory to search in. Defaults to workspace root.',
      },
      maxResults: {
        type: 'integer',
        description: 'Maximum results to return (default: 100, max: 500).',
      },
    },

    output: {
      schema: {
        type: 'object',
        properties: {
          files: {
            type: 'array',
            items: { type: 'string' },
          },
          total: { type: 'integer' },
          truncated: { type: 'boolean' },
          searchPath: { type: 'string' },
        },
        additionalProperties: false,
      },

      render: (_args, value) => {
        const v = value as {
          files: string[]; total: number; truncated: boolean; searchPath: string
        }
        const lines = [`Search results in ${v.searchPath} for pattern "${_args.pattern}":`]
        if (v.files.length === 0) {
          lines.push('(no matches found)')
        } else {
          lines.push(`Found ${v.total} file(s), showing ${v.files.length}:`)
          lines.push('')
          for (const f of v.files) lines.push(`  ${f}`)
          if (v.truncated) lines.push('  ... (results truncated)')
        }
        return [{ type: 'text', text: lines.join('\n') }]
      },
    },

    async execute(args, _exec) {
      const root = args.path || '.'
      const max = Math.min(args.maxResults ?? 100, 500)

      // 用 ctx.fs 替代裸 fs 模块——统一的路径解析
      const target = await ctx.fs.resolve(root)
      const displayPath = target.displayPath

      // 列出目录（只列一层，演示 ctx.fs.listDir）
      let entries: { name: string; type: string }[]
      try {
        const dirEntries = await ctx.fs.listDir(target)
        entries = dirEntries.map(e => ({ name: e.name, type: e.type }))
      } catch (err: any) {
        const code = err?.code ?? 'FS_IO_ERROR'
        if (code === 'FS_PERMISSION_DENIED') {
          throw new Error(`Permission denied: cannot list directory ${displayPath}`)
        }
        throw new Error(`Failed to list directory ${displayPath}: ${err?.message ?? code}`)
      }

      // 简单 glob 匹配（生产环境可用 ripgrep、fast-glob 等）
      // 这里为示例做一个简化实现：将 glob 转为正则
      const regexStr = args.pattern
        .replace(/\./g, '\\.')
        .replace(/\*\*/g, '___GLOBSTAR___')
        .replace(/\*/g, '[^/]*')
        .replace(/___GLOBSTAR___/g, '.*')
      const regex = new RegExp(`^${regexStr}$`)

      const results: string[] = []
      for (const entry of entries) {
        if (results.length >= max) break
        if (regex.test(entry.name)) {
          results.push(entry.name)
        }
      }

      return {
        files: results,
        total: results.length,
        truncated: results.length > max,
        searchPath: displayPath,
      }
    },
  }))
}
```

### 代码：一个带截断的文件读取工具

```ts
// scratch-plugin/src/read.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'read-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'read_file_safe',
    description: 'Read a UTF-8 text file with line windowing and size limit.',

    parameters: {
      path: {
        type: 'string',
        required: true,
        description: 'Absolute or workspace-relative path to the file.',
      },
      offset: {
        type: 'integer',
        description: '1-based first line to return (default: 1).',
      },
      limit: {
        type: 'integer',
        description: 'Maximum number of lines to return (default: 2000, max: 5000).',
      },
    },

    output: {
      schema: {
        type: 'object',
        properties: {
          path: { type: 'string' },
          lines: {
            type: 'array',
            items: {
              type: 'object',
              properties: {
                number: { type: 'integer' },
                text: { type: 'string' },
              },
              additionalProperties: false,
            },
          },
          totalLines: { type: 'integer' },
          truncated: { type: 'boolean' },
        },
        additionalProperties: false,
      },

      render: (_args, value) => {
        const v = value as {
          path: string; lines: Array<{ number: number; text: string }>
          totalLines: number; truncated: boolean
        }
        const content = v.lines.map(l => `${l.number}: ${l.text}`).join('\n')
        let text = `File: ${v.path} (${v.totalLines} lines total)\n\n${content}`
        if (v.truncated) text += '\n... (output truncated)'
        return [{ type: 'text', text }]
      },
    },

    async execute(args, _exec) {
      const offset = args.offset ?? 1
      const limit = Math.min(args.limit ?? 2000, 5000)

      // 使用 ctx.fs 解析路径
      const target = await ctx.fs.resolve(args.path)
      const displayPath = target.displayPath

      // 先 stat 检查类型和大小
      let meta
      try {
        meta = await ctx.fs.stat(target)
      } catch (err: any) {
        throw new Error(`Cannot access file: ${err?.message ?? 'FS_IO_ERROR'}`)
      }

      if (!meta) {
        return {
          path: displayPath, lines: [], totalLines: 0, truncated: false,
        }
      }

      if (meta.type !== 'file') {
        throw new Error(`Not a regular file: ${displayPath} is ${meta.type}`)
      }

      // 读取全部文本（小文件场景）或流式读取
      let text: string
      try {
        // 1MB 上限（含），超过则截断
        const MAX_BYTES = 1 * 1024 * 1024
        const bytes = await ctx.fs.readBytes(target, undefined, MAX_BYTES)
        text = new TextDecoder('utf-8', { fatal: true }).decode(bytes)
      } catch (err: any) {
        if (err?.code === 'FS_TOO_LARGE') {
          throw new Error(`File too large: ${displayPath} exceeds max size`)
        }
        if (err?.code === 'FS_NOT_TEXT') {
          throw new Error(`Not a text file: ${displayPath} is binary or uses unsupported encoding`)
        }
        if (err?.code === 'FS_PERMISSION_DENIED') {
          throw new Error(`Permission denied: cannot read ${displayPath}`)
        }
        throw new Error(`Failed to read ${displayPath}: ${err?.message ?? 'FS_IO_ERROR'}`)
      }

      const allLines = text.split('\n')
      const totalLines = allLines.length

      // 窗口截取
      const startIdx = Math.max(0, offset - 1)
      const slice = allLines.slice(startIdx, startIdx + limit)

      const lines = slice.map((line, i) => ({
        number: startIdx + i + 1,
        text: line,
      }))

      const truncated = startIdx + limit < totalLines

      return { path: displayPath, lines, totalLines, truncated }
    },
  }))
}
```

### 边界情况处理

两个文件系统工具都处理了以下边界情况：

| 边界情况 | 处理方式 |
|---|---|
| 路径不存在 | 返回空结果（非错误） |
| 权限不足 | 抛出明确错误信息 |
| 二进制文件 | 检查是否为文本文件 |
| 大文件 | 限制最多读取 1MB 字节 |
| 大目录 | 限制最多返回 500 条结果 |
| 符号链接 | `ctx.fs.resolve` 自动处理 |

### 同步 vs 异步的选择

第 4 章的工具使用 `fs.readFileSync`，因为它们是一次性的、同步的、不依赖外部服务的操作。本章的工具全部使用 `ctx.fs` 的异步 API：

- `ctx.fs` 本身是抽象 seam，后端可能是远程或沙箱化的，必须异步
- 异步接口允许取消传播（通过 `AbortSignal`）
- 即使本地后端，`resolve()` 也需要执行 realpath，可能是 I/O 操作

**规则**：工具内部调用 `ctx.*` 服务时必须用其异步 API；只有纯计算逻辑可以用同步方式。

## 5.2 Shell 命令工具

### 场景

让 AI 能执行 Shell 命令来安装依赖、运行测试、检查环境。

`ctx.shell` 服务提供了统一的 Shell 执行抽象。它和直接 `spawn` 的最大区别是：

1. **标准化接口**：`ShellExecRequest` → `resolve()` → `run()`，参数补全和封顶统一处理
2. **超时控制**：自带超时机制，超时 + 被杀死的独立上报
3. **stdout/stderr 分开捕获**：带截断和 spill 恢复
4. **沙箱集成**：自动感知沙箱策略
5. **凭据清理**：自动从环境变量中移除密钥

### 代码：一个命令执行工具

```ts
// scratch-plugin/src/shell.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'shell-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  ctx.tools.register(defineTool({
    name: 'run_command',
    description: 'Execute a shell command and capture stdout/stderr. Each call runs in a new shell — state is NOT preserved between calls.',

    parameters: {
      command: {
        type: 'string',
        required: true,
        description: 'The shell command to execute.',
      },
      workdir: {
        type: 'string',
        description: 'Working directory. Defaults to workspace root.',
      },
      timeoutMs: {
        type: 'integer',
        description: 'Timeout in milliseconds (default: 30000, max: 120000).',
      },
      description: {
        type: 'string',
        description: 'Brief description of what this command does (5-10 words).',
      },
    },

    output: {
      schema: {
        type: 'object',
        properties: {
          exitCode: { type: ['integer', 'null'] },
          stdout: { type: 'string' },
          stderr: { type: 'string' },
          timedOut: { type: 'boolean' },
          signal: { type: ['string', 'null'] },
          command: { type: 'string' },
        },
        additionalProperties: false,
      },

      render: (_args, value) => {
        const v = value as {
          exitCode: number | null; stdout: string; stderr: string
          timedOut: boolean; signal: string | null; command: string
        }
        const parts: string[] = []

        if (v.stdout) parts.push(v.stdout)

        if (v.stderr) {
          parts.push('')
          parts.push('--- stderr ---')
          parts.push(v.stderr)
        }

        if (v.signal) {
          parts.push(`\n[Killed by signal: ${v.signal}]`)
        } else if (v.timedOut) {
          parts.push('\n[Command timed out]')
        } else if (v.exitCode !== 0) {
          parts.push(`\n[Exit code: ${v.exitCode}]`)
        }

        return [{ type: 'text', text: parts.join('\n') }]
      },
    },

    async execute(args, exec) {
      const timeoutMs = Math.min(args.timeoutMs ?? 30000, 120000)

      // 1. 构建请求
      const request = {
        command: args.command,
        workdir: args.workdir,
        timeoutMs,
        signal: exec.signal,
        // 前台执行，不设 stdin
      }

      // 2. 通过 resolve 补全和封顶默认值
      const spec = ctx.shell.resolve(request)

      // 3. 执行
      let result
      try {
        result = await ctx.shell.run(spec)
      } catch (err: any) {
        // 基础设施错误（非命令错误）
        throw new Error(`Shell execution failed: ${err?.message ?? 'unknown error'}`)
      }

      // 4. 整理结果
      return {
        exitCode: result.exitCode,
        stdout: result.stdout.text,
        stderr: result.stderr.text,
        timedOut: result.timedOut,
        signal: result.signal,
        command: args.command,
      }
    },
  }))
}
```

### 运行说明

```sh
pnpm dsh web --patch ./scratch-plugin/cordis.yml
```

在对话框中输入：

> Run `ls -la` to list files in the workspace root.

AI 会调用 `run_command` 工具，参数为 `{ command: "ls -la" }`。如果命令执行成功，你会看到类似这样的输出：

```
total 42
drwxr-xr-x  12 user staff  384 Aug 29 10:00 .
drwxr-xr-x  24 user staff  768 Aug 29 09:55 ..
...
```

### stdout/stderr 分开捕获

`ShellRunResult` 包含独立的 `stdout` 和 `stderr`，每个又是一个 `CollectedOutput` 对象（包含 `text` 和截断信息）：

```ts
interface CollectedOutput {
  text: string       // 文本内容（可能截断）
  truncated: boolean // 是否被截断
  spillPath?: string // 完整输出的 spill 文件路径（如有）
}
```

这样设计的好处是：AI 可以分别查看正常输出和错误输出，而不是混在一起。

### Shell 注入防范注意事项

`ctx.shell` 本身不执行命令——它把命令字符串传给操作系统。防范注入的责任在工具的实现层：

1. **不要拼接用户输入到命令中**：如果必须传参，使用 shell 的引用机制或 `process.spawn` 的参数数组模式
2. **凭据自动清理**：`ctx.shell` 实现会自动从环境中移除名称匹配 `*KEY*`、`*SECRET*`、`*TOKEN*` 或 `*PASSWORD*` 的变量
3. **超时兜底**：始终设置合理的 `timeoutMs`，防止命令挂起
4. **沙箱**：在受限模式下，文件操作会被自动拒绝

## 5.3 持久终端

### 场景

`ctx.shell` 每次执行都在新进程中运行——`cd` 不会保留、导出的变量不会保留。当你需要 AI 在同一个 shell 中连续执行多条命令（例如进入目录、激活虚拟环境、然后运行命令），就需要持久终端。

`ctx.terminals` 服务提供按 agent 隔离的 PTY 会话。它和 `ctx.shell` 的关键区别：

| 方面 | ctx.shell | ctx.terminals |
|---|---|---|
| 每次调用 | 新进程 | 同一会话 |
| 状态保留 | 不保留 (cwd、变量) | 保留 |
| 超时 | 有（可配置） | 无（通过 job 管理） |
| 交互性 | 无交互 | 支持 stdin/stdout |
| 适用场景 | 一次性命令 | 多步操作序列 |

### 何时用哪个

- **`ctx.shell`**（一次性执行）：安装一个包、运行一个测试、获取目录列表。命令之间无状态依赖。
- **`ctx.terminals`**（持久会话）：进入项目目录 → 激活 venv → 运行开发服务器 → 另一条命令在同一个 venv 上下文中运行。

### 代码：一个持久终端工具

```ts
// scratch-plugin/src/terminal.ts
import type { Context } from '@deepseek-ai/cordis'
import { defineTool } from '@deepseek-ai/dsh-tools'

export const name = 'terminal-tool'
export const inject = ['tools']

export function apply(ctx: Context) {
  // 创建一个持久终端会话
  let sessionId: string | null = null

  ctx.tools.register(defineTool({
    name: 'terminal_send',
    description: 'Send a command to a persistent terminal session. The session keeps state (cwd, env) between calls.',

    parameters: {
      command: {
        type: 'string',
        required: true,
        description: 'The command to run in the persistent terminal.',
      },
      cwd: {
        type: 'string',
        description: 'Initial working directory (only used when opening a new session).',
      },
    },

    output: {
      schema: {
        type: 'object',
        properties: {
          output: { type: 'string' },
          sessionId: { type: 'string' },
          exitCode: { type: ['integer', 'null'] },
        },
        additionalProperties: false,
      },

      render: (_args, value) => {
        const v = value as {
          output: string; sessionId: string; exitCode: number | null
        }
        const parts = [`[Session: ${v.sessionId}]`]
        if (v.output) parts.push(v.output)
        if (v.exitCode !== null) parts.push(`[Exit code: ${v.exitCode}]`)
        return [{ type: 'text', text: parts.join('\n') }]
      },
    },

    async execute(args, exec) {
      // 首次调用时打开一个新的终端会话
      if (!sessionId) {
        const spawnResult = await ctx.terminals.spawn(
          exec.agent!,
          { type: 'shell', cwd: args.cwd },
          exec.signal,
        )
        sessionId = spawnResult.id
      }

      // 发送命令并等待输出
      const op = ctx.terminals.startSend(
        exec.agent!,
        sessionId,
        { text: args.command, submit: true },
      )
      const sendResult = await op.done

      const status = sendResult.sessionStatus
      const exitCode = status.kind === 'exited' ? status.exitCode : null

      return {
        output: sendResult.viewport,
        sessionId,
        exitCode,
      }
    },
  }))

  // 插件卸载时清理终端会话
  ctx.on('dispose', async () => {
    if (sessionId) {
      await ctx.terminals.kill(
        // 注意：exec.agent 在 dispose 时可能已不可用
        // 生产环境中应通过其他方式传递 owner
        sessionId,
        'plugin dispose',
      )
    }
  })
}
```

## 5.4 后台任务

### 场景

有些命令运行时间很长——启动开发服务器、运行大型测试套件、下载文件。如果工具在前台等待，AI 会卡住，用户也干等着。Harness 通过 `ctx.jobs` 服务支持后台任务模式。

后台任务的流程是：

1. 工具通过 `ctx.jobs.start()` 注册一个后台任务，获得 job id
2. 工具立即返回，告诉 AI "任务已启动，id 是 bash-1"
3. AI 之后可以通过 `job_output`、`job_list`、`job_kill` 等工具查询和控制任务

### ctx.jobs API 核心方法

```ts
interface JobRegistry {
  start(spec: JobStart): JobId          // 启动后台任务
  get(id: JobId, caller?: Agent): JobSnapshot  // 查询任务状态
  list(caller?: Agent): JobSnapshot[]   // 列出所有可见任务
  read(id: JobId, caller?: Agent): JobRead     // 读取输出
  kill(id: JobId, caller?: Agent, reason?: string): 'requested' | 'already-finished'
  wait(id: JobId, timeoutMs: number, caller?: Agent, signal?: AbortSignal): Promise<JobSnapshot>
}
```

### 前台 vs 后台模式

| | 前台模式 | 后台模式 |
|---|---|---|
| 等待完成 | 是，等到命令退出或超时 | 否，启动即返回 |
| 超时 | 有（timeoutMs） | 无 |
| 结果获取 | execute 返回值中直接包含 | 通过 job_output 单独获取 |
| 取消 | 通过 exec.signal | 通过 job_kill |
| 适用场景 | 快速命令（< 30s） | 长时间运行的任务 |

### 代码：后台任务支持

在 `run_command` 工具中增加后台模式：

```ts
parameters: {
  command: { type: 'string', required: true, description: 'The shell command' },
  description: { type: 'string', description: 'Brief description' },
  run_in_background: {
    type: 'boolean',
    description: 'Run in background and return a job id immediately.',
  },
},
```

后台分支的 execute 逻辑：

```ts
async execute(args, exec) {
  if (args.run_in_background) {
    // 后台模式
    const spec = ctx.shell.resolve({ command: args.command })
    const process = ctx.shell.start(spec)

    const jobId = ctx.jobs.start({
      kind: 'bash',
      label: args.command,
      owner: exec.agent,
      run: () => ({
        done: process.done.then(() => {
          const exit = process.exitCode
          return {
            status: exit !== null ? 'completed' : 'killed',
            detail: exit !== null ? `exit code: ${exit}` : undefined,
            output: process.readOutput().delta,
          }
        }),
        cancel: () => process.kill(),
        readOutput: () => process.readOutput().delta,
      }),
    })

    return { kind: 'background', jobId }
  }

  // 前台模式（同 5.2 节）
  // ...
}
```

## 5.5 工具的执行管道

工具从被模型选择到最终结果呈现给模型，经过了一条完整的管道。理解它有助于编写更好的工具和调试问题。

### 流程概览

```
模型发出 tool-call
    ↓
tools/pre-execute (waterfall)  ← 权限检查、沙箱
    ↓
单调守卫 (guard)  ← 最终拒绝（不可撤销）
    ↓
tools/execute (waterfall)  ← 超时、重试、指标
    ↓
工具 execute() 函数体
    ↓
tools/post-execute (waterfall)  ← 结果变换、上下文附加
    ↓
normalize + finalizeContent  ← 注册表归一化 + 工具自身内容回调
    ↓
tools/result (emit)  ← 不可变结果观测
    ↓
模型收到 tool-result
```

### pre-execute：权限检查

`tools/pre-execute` 是一个 waterfall 事件。监听器可以：

- `allow`：允许执行
- `deny`：拒绝，返回错误信息给模型
- `ask`：询问用户确认

下面是一个监听 `tools/pre-execute` 做权限控制的例子：

```ts
// 在 apply 中注册
ctx.on('tools/pre-execute', async (exec, next) => {
  // 对 run_command 工具做权限控制
  if (exec.name === 'run_command') {
    const command = (exec.arguments as any)?.command ?? ''
    // 拒绝 rm -rf /
    if (command.includes('rm -rf /') || command.includes('rm -rf /*')) {
      return { kind: 'deny', reason: 'Destructive command is not allowed: rm -rf /' }
    }
    // 高危操作需要用户确认
    if (command.startsWith('sudo ') || command.includes('> /dev/sda')) {
      return { kind: 'ask', reason: `Confirm running: ${command}` }
    }
  }
  // 默认放行
  return next()
})
```

### execute：核心执行

注册的工具 `execute()` 函数体在 `tools/execute` waterfall 内部被调用。这个 waterfall 可以被超时策略、重试策略包装。`@deepseek-ai/dsh-tool-call-timeout-policy` 就是一个 `tools/execute` 的包装层——它替换 `exec.signal` 加上截止时间，超时后中止调用。

### post-execute：结果变换

执行完成后，`tools/post-execute` 可以对结果做变换：

```ts
ctx.on('tools/post-execute', async (exec, result, next) => {
  // 给所有 shell 命令结果附加提示
  if (exec.name === 'run_command' && !result.isError) {
    return {
      kind: 'accept',
      content: [
        ...result.content,
        { type: 'text', text: '\n\n> Tip: use run_in_background for long-running commands.' },
      ],
    }
  }
  return next()
})
```

### result：不可变观测

最后，`tools/result` 事件发射时，结果已经冻结，监听器只能观察不能修改：

```ts
ctx.on('tools/result', (exec, result) => {
  // 记录工具执行日志
  console.log(`[tool:${exec.name}] isError=${result.isError}, agent=${exec.agent?.id}`)
})
```

## 5.6 工具的 UI 卡片

在 Web UI 中，工具调用和结果显示为卡片。Harness 为不同类型的工具提供了专门的卡片样式，不需要每个工具自己写 HTML。

### 卡片类型

| 卡片类型 | 用途 | 示例 |
|---|---|---|
| `generic` | 默认通用卡片 | greet 问候工具 |
| `terminal` | Shell 命令 | run_command |
| `diff` | 文件变更 | write/edit |
| `read` | 文件读取 | read_file_safe |
| `search` | 搜索类结果 | grep/glob |
| `web` | 网络请求 | web_search/web_fetch |

### presentCall 和 presentResult

工具可以通过 `presentCall` 和 `presentResult` 方法声明卡片渲染意图。它们是纯函数，不依赖 I/O 或外部状态。

下面是给 `run_command` 添加终端卡片的例子：

```ts
defineTool({
  // ... name, parameters, execute 等

  presentCall(args) {
    return {
      card: 'terminal',
      title: (args as any).command,
      description: (args as any).description,
      cwd: (args as any).workdir,
    }
  },

  presentResult(args, result) {
    if (result.isError) return undefined  // 错误时用通用回退
    const content = result.content.map(b => b.text).join('\n')
    return {
      card: 'terminal',
      output: content,
      exitCode: (args as any).exitCode ?? null,
    }
  },
})
```

### 纯函数要求

`presentCall` 和 `presentResult` 必须是纯函数——它们会在 **实时流式传输** 和 **会话回放** 两个场景中被调用。所以：

- 不能做 I/O（读文件、发网络请求）
- 不能访问时钟或随机数
- 不能依赖可变的外部状态
- 返回 `undefined` 则回退到通用卡片

### 回放支持

`presentResult` 接收的 `result` 对象是持久化的——它包括 `content`、`isError`、`meta`（来自 `presentationMeta`）。这样，当用户回看历史会话时，卡片能还原出和当初一样的视觉效果，而无需重新执行工具。

## 5.7 本章小结

这一章把你从"写一个能跑的工具"带到了"写一个生产级的工具"。你学到的核心内容：

**文件系统工具** — 使用 `ctx.fs` 服务替代裸 `fs` 模块，获得统一的路径解析、错误分类、沙箱感知和观测策略支持。处理了权限不足、大文件截断、二进制文件等边界情况。

**Shell 命令工具** — 使用 `ctx.shell` 服务执行一次性命令，`stdout`/`stderr` 分开捕获，超时控制，退出码判断。理解了 Shell 注入防范的要点。

**持久终端** — 使用 `ctx.terminals` 创建保持状态的 Shell 会话。明确了何时用一次性执行 vs 持久会话。

**后台任务** — 使用 `ctx.jobs` 管理长时间运行的任务。支持前台/后台两种模式，通过 job id 查询状态、读取输出、取消任务。

**执行管道** — 理解了工具的完整生命周期：`pre-execute`（权限检查）→ `guards`（单调守卫）→ `execute`（核心执行）→ `post-execute`（结果变换）→ `normalize`（归一化）→ `result`（不可变观测）。

**UI 卡片** — 掌握了 `presentCall`/`presentResult` 纯函数，以及 `terminal`、`diff`、`read`、`search` 等卡片类型。

这些模式覆盖了你在真实场景中 90% 的工具开发需求。第 6 章将讨论 LLM 与大模型的集成——如何让你的工具和模型能力协同工作。
